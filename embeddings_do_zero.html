O que é um embedding?

Imagine que palavras fossem casas numa cidade enorme. Casas parecidas moram no mesmo bairro. Um embedding é o endereço secreto de cada casa — um conjunto de números que o computador usa para achar vizinhos.

Nesta página você vai construir, medir e buscar embeddings com as próprias mãos. Sem jargão antes da analogia. Sem magia preta.

Capítulo 1 O problema

Computadores não entendem palavras

Você abre um texto e aperta Ctrl+F para achar a palavra “cão”. Mas o texto só escreveu “cachorro”. O computador responde: “não achei”. Ele é literal. Para ele, cão e cachorro são tão diferentes quanto cão e helicóptero.

O computador lê letras. Humanos leem significado. Embeddings existem para ensinar significado ao computador.

Capítulo 2 A grande ideia

Dar um endereço a cada palavra

Imagine uma cidade onde palavras moram. Palavras parecidas moram no mesmo bairro. “Cachorro” mora perto de “gato” e “animal”. “Pizza” mora perto de “hambúrguer”. “Triste” mora perto de “chorar”.

O endereço de cada palavra é uma lista de números — as coordenadas no mapa. Isso se chama embedding (do inglês to embed = encaixar, embutir).

Capítulo 3 Construindo

Faça um embedding com as próprias mãos

Em vez de deixar o computador inventar as dimensões, vamos inventar quatro perguntas humanas. Cada pergunta vira um número de 0 a 10. Juntas, formam o endereço (o vetor) da coisa.

Modelos reais fazem a mesma coisa — só que com 384, 768 ou 1536 perguntas secretas, aprendidas automaticamente a partir de bilhões de textos. Ninguém escolhe as perguntas à mão. O resultado é um endereço muito mais rico.
Capítulo 4 Medindo

Como medir “parecença”?

Dois amigos apontam com o braço. Se apontam para o mesmo lado, estão alinhados. Se apontam para lados opostos, discordam. Em embeddings, medimos o ângulo entre dois endereços. O nome técnico dessa medida é similaridade de cosseno.

A fórmula — pedaço por pedaço

cos(θ) = (A · B) / (|A| × |B|)
“Cosseno do ângulo entre A e B = produto escalar dividido pelos comprimentos”
A · B
Produto escalar (dot product)

Multiplique número com número na mesma posição e some tudo. Ex.: A=(3, 4) e B=(1, 2) → 3×1 + 4×2 = 11. Quanto mais “apontam juntos”, maior o resultado.

|A| e |B|
Comprimento (norma)

É o tamanho da seta: |A| = √(3² + 4²) = 5. Dividimos pelos comprimentos para ignorar o tamanho e olhar só a direção — textos longos não “ganham” só por serem longos.

cos(θ)
O resultado final

Sai um número entre −1 e +1. Perto de +1 = mesma direção (parecidos). Perto de 0 = perpendiculares (sem relação). Perto de −1 = opostos.

Exemplo completo com números de verdade
Passo Conta
1. Vetores A = (3, 4)   B = (4, 3)
2. A · B 3×4 + 4×3 = 12 + 12 = 24
3. |A| √(3²+4²) = √25 = 5
4. |B| √(4²+3²) = √25 = 5
5. cos 24 / (5×5) = 24/25 = 0,96 → quase iguais!

Por que não usamos só a distância euclidiana (régua no mapa)? Porque dois textos sobre o mesmo assunto podem ter vetores de tamanhos diferentes. O cosseno pergunta: “apontam para o mesmo lado?” — e isso é o que importa para significado.

Capítulo 7 Índices

E quando são milhões de pontos?

Até aqui você entendeu o embedding: cada texto vira um ponto num mapa. Para achar a resposta, comparamos a pergunta com os documentos e pegamos os mais próximos (maior cosseno).

Com 20 frases, isso é fácil: compare com todas. Com 10 milhões de documentos, cada um com 1536 números, comparar com todos a cada pergunta seria como visitar todas as casas do país para achar a padaria mais perto. Funciona. É absurdamente lento.

O índice é o atalho: uma estrutura que organiza os embeddings para achar vizinhos sem olhar todo mundo. A busca aproximada se chama ANN (Approximate Nearest Neighbor).

O que é um índice, em linguagem humana?

Pense no índice remissivo de um livro: em vez de ler página por página, você vai direto ao assunto. No mundo dos embeddings, o índice não organiza por palavra — organiza por posição no mapa. Ele responde: “quais pontos estão perto deste endereço?”.

Sem índice (busca exata)

Para cada pergunta: calcule o cosseno com todos os N documentos. Custo: O(N × d) — N documentos × d dimensões. Com N = 1.000.000 e d = 1536, são bilhões de multiplicaçoes por consulta.

Com índice (ANN)

Na indexação (uma vez): organizamos os pontos em bairros ou num grafo de atalhos. Na consulta: visitamos só uma fração dos pontos. Custo cai para milissegundos — às vezes trocando 1–5% de acerto.

Ligação direta com o capítulo anterior: o embedding cria o mapa; o índice navega o mapa. Um sem o outro não faz busca semântica em escala.

Força bruta (Flat / Exact)

O que significa

Não é uma sigla — é o método sem índice sofisticado. Também chamado de Flat (Faiss), exact k-NN ou brute-force. Você compara a consulta com todos os N vetores, dimensão por dimensão.

Como funciona
  1. Recebe o vetor da pergunta (d dimensões).
  2. Calcula distância/cosseno contra cada um dos N documentos.
  3. Ordena e devolve os k melhores. Sem atalho.

Custo: O(N × d) por consulta

Quando usar
  • · Corpus pequeno (até ~50–100 mil vetores)
  • · Precisa de recall 100% (avaliação, auditoria)
  • · Baseline para medir a qualidade do ANN
  • · Prototipagem rápida, sem tunar parâmetros
Quando NÃO usar
  • · Milhões de vetores em produção interativa
  • · SLA de latência em milissegundos com N grande
  • · Quando a fatura de CPU/GPU explode
Onde aparece: Faiss IndexFlatL2 / IndexFlatIP, NumPy puro, scikit-learn NearestNeighbors, ChromaDB em modo exato em coleções pequenas.
Família

ANN — Approximate Nearest Neighbor

Approximate = aproximado · Nearest Neighbor = vizinho mais próximo. Não é um algoritmo — é a categoria que agrupa IVF, HNSW, DiskANN, Annoy, ScaNN… A ideia comum: aceitar errar 1–5% dos vizinhos em troca de ser ordens de magnitude mais rápido.

O “preço” do ANN se chama perda de recall. O que o índice não devolve, nenhuma etapa posterior (reranker, LLM) recupera.

Partição

IVF — Inverted File Index

O que cada letra significa
  • Inverted — invertido: em vez de “documento → termos”, o índice guarda “célula/bairro → lista de vetores que caíram ali” (a mesma ideia do índice invertido clássico de busca textual).
  • File — arquivo/estrutura que materializa essas listas.
  • Index — índice: a organização que acelera a busca.
Como funciona (passo a passo)
  1. Treino: roda um clustering (k-means) e cria nlist centróides — cada um é o “centro do bairro”.
  2. Indexação: cada vetor do corpus é atribuído ao centróide mais próximo e entra na lista daquela célula.
  3. Consulta: acha os nprobe centróides mais perto da pergunta e só compara os vetores dessas células.
Parâmetros que importam
nlist — quantos bairros criar na indexação. Mais bairros = células menores.
nprobe — quantos bairros visitar na consulta. O botão de recall × latência.
IVF-PQ — a dupla clássica

PQ = Product Quantization (quantização por produto). Corta cada vetor em subespaços e comprime cada pedaço num código curto. IVF escolhe quais células visitar; PQ deixa cada comparação mais barata em memória e CPU. Compressão típica: 10–50×. O preço: um pouco mais de perda de recall — mitigue com rescoring dos candidatos em float32.

Quando usar
  • · Milhões de vetores e RAM é o gargalo
  • · Aceita recall ~0,90–0,96 com rescoring
  • · Quer melhor GB por real investido
  • · Batch / throughput importa mais que p99 mínimo
Quando NÃO usar
  • · Precisa de recall muito alto com baixa latência
  • · Corpus pequeno (força bruta ou HNSW são mais simples)
  • · nprobe mal calibrado → recall cai sem você perceber
Onde aparece: Faiss IndexIVFFlat / IndexIVFPQ, Milvus (IVF_FLAT, IVF_PQ), Vespa, OpenSearch k-NN (Faiss IVF).
Grafo · padrão de mercado

HNSW — Hierarchical Navigable Small World

O que cada palavra significa
  • Hierarchical — hierárquico: várias camadas de grafo, como níveis de zoom num mapa.
  • Navigable — navegável: a partir de qualquer ponto dá para caminhar até a região certa seguindo arestas.
  • Small World — mundo pequeno: a propriedade de redes sociais — poucos saltos ligam pontos distantes (atalhos longos + vizinhos locais).

Paper clássico: Malkov & Yashunin, 2018. É o algoritmo por trás da maioria dos vector stores atuais.

Como funciona (a analogia avião → ônibus → a pé)
  1. Camada alta: poucos nós, arestas longas — “voo” até a região certa do espaço (avião).
  2. Camadas do meio: mais nós, saltos médios — aproxima do bairro (ônibus).
  3. Camada 0 (base): todos os pontos, arestas curtas — refina até o vizinho (a pé).
  4. Em cada passo: olha os vizinhos do nó atual e vai para o mais próximo da consulta (busca gulosa + fila de candidatos).
Parâmetros que importam
M — conexões por nó. Maior M = mais recall e mais RAM.
efConstruction — qualidade do grafo na construção (pago uma vez).
efSearch — tamanho da fila na consulta. O botão recall × latência.
Quando usar
  • · Produção RAG com centenas de mil a poucos milhões
  • · Índice cabe em RAM e latência p95 importa
  • · Quer alto recall sem tunar demais
  • · Padrão em pgvector, Qdrant, Weaviate, Chroma, Redis…
Quando NÃO usar (ou usar com cuidado)
  • · Bilhões de vetores sem RAM suficiente → DiskANN
  • · Deleções frequentes: remoção costuma ser lógica (tombstone) e degrada o grafo
  • · Corpus minúsculo: força bruta é mais simples
Onde aparece: pgvector (HNSW), Qdrant, Weaviate, ChromaDB, Milvus (HNSW), Redis Vector, Elasticsearch/OpenSearch, Faiss IndexHNSWFlat.
Escala de bilhões

DiskANN — Disk-based Approximate Nearest Neighbor

O que significa

Disk = o grafo mora no SSD · ANN = busca aproximada. Criado pela Microsoft (2019). Mantém um cache comprimido em RAM e faz saltos com leituras aleatórias rápidas em NVMe. Variante com filtros: Filtered-DiskANN (2023).

Quando usar
  • · Centenas de milhões a bilhões de vetores
  • · Custo de RAM seria proibitivo com HNSW puro
  • · Aceita latência de dezenas de ms (ainda ok p/ RAG)
Quando NÃO usar
  • · Corpus cabe confortável em RAM → HNSW é mais simples
  • · SSD ruim / IOPS baixos (o disco vira o gargalo)
  • · Time sem maturidade ops para tunar I/O
Onde aparece: Azure AI Search, SpaceV / DiskANN open-source (Microsoft), alguns modos de escala em bancos gerenciados.

Guia rápido de decisão

Sua situação Escolha
Lab, demo, < 100 mil vetores Força bruta — simples e correta
Produção, índice cabe em RAM, latência importa HNSW — padrão da indústria
Muitos milhões, RAM cara, aceita recall um pouco menor IVF-PQ — melhor custo/GB
Escala de bilhões, SSD NVMe disponível DiskANN — grafo no disco

Regra prática: comece com HNSW (ou força bruta se for pequeno). Só migre para IVF-PQ/DiskANN quando a medição (RAM ou latência) mostrar que precisa. Aprofunde parâmetros e filtros em rag_agentic.html#indices.

Embed da pergunta → vizinhos

Na consulta: (a) transformamos a pergunta num embedding com o mesmo modelo usado nos documentos; (b) o índice devolve os k vizinhos mais próximos; (c) esses trechos vão para o LLM responder. Se o índice errar o vizinho certo aqui, o LLM nunca o vê.

Um detalhe que pega todo mundo: filtros

Em sistemas reais você não quer “qualquer documento parecido” — quer só os vigentes, do seu tenant, com permissão. Combinar “mais parecidos” + “que passam no filtro” é surpreendentemente difícil.

Pós-filtro
Busca top-k e depois descarta. Pode sobrar zero resultados se o filtro for seletivo.
Pré-filtro
Filtra primeiro, busca depois. Bom se o subconjunto for pequeno.
Filtro nativo
O índice aplica o predicado durante a travessia. Preferível quando o banco oferece.

Aprofunde em rag_agentic.html#indices — lá tem o caso da norma revogada e o código do filtro certo.

Capítulo 8 O preço

O preço do atalho: recall × velocidade

ANN troca um pouquinho de acerto por muito ganho de velocidade. Esse “pouquinho” perdido não volta depois — o reranker só reordena o que chegou. Por isso medimos recall: “dos vizinhos certos, quantos eu achei?”.

Recall do ANN

Compara o resultado aproximado com a busca exata. Responde: “o índice está bem calibrado?”. Se recall@10 = 0,95, em 95% dos casos o vizinho verdadeiro está entre os 10 devolvidos.

Recall do sistema

Compara o que foi recuperado com o que deveria ter sido (anotação humana). Mede embedding + chunking + índice juntos. Um índice perfeito sobre embeddings ruins ainda entrega lixo.

Latência × recall (famílias ANN)

Cada ponto no gráfico é um “ajuste” possível. Quanto mais à esquerda, mais rápido; quanto mais acima, mais acerto. O ideal fica no canto superior esquerdo — e cada família tem seu lugar.

Força bruta
Recall 1.0, latência alta. Só para índices pequenos.
HNSW
Quando o índice cabe em RAM e latência manda.
IVF-PQ
Quando RAM é o gargalo; compressão agressiva.
DiskANN
Bilhões de vetores; grafo no SSD.

Botões práticos: em HNSW aumente efSearch até o recall estabilizar; em IVF aumente nprobe. Medir no seu corpus vale mais que teorizar.

Lição de ouro: um índice com recall 0,99 sobre embeddings ruins continua entregando lixo — só que muito rápido. Embedding e índice são duas engrenagens. As duas precisam estar boas.

Glossário ilustrado

Embedding
O endereço secreto de um texto — uma lista de números que captura significado.
Vetor
A lista de números em si. Em 2D: (x, y). Em 1536D: 1536 números.
Dimensão
Uma “pergunta” do endereço. Mais dimensões = mais nuances.
Cosseno
Medida de alinhamento entre dois vetores. 1 = mesma direção, 0 = ortogonais, −1 = opostos.
ANN
Approximate Nearest Neighbor — busca aproximada do vizinho mais próximo (família: IVF, HNSW, DiskANN…).
IVF
Inverted File Index — divide o espaço em “bairros” (células) e só visita os mais próximos (nprobe).
PQ
Product Quantization — comprime vetores em códigos curtos; com IVF vira IVF-PQ (economiza muita RAM).
Recall
Dos vizinhos certos, quantos realmente foram encontrados.
Índice
Estrutura que organiza os embeddings para busca rápida (grafo, células…).
HNSW
Hierarchical Navigable Small World — grafo em camadas com atalhos (avião → ônibus → a pé); padrão de mercado.
DiskANN
ANN com grafo no SSD — para bilhões de vetores quando a RAM não basta.
